# scol-ui

The sc-offline launcher window in Rust: eframe 0.37 / egui 0.37, glow renderer, no bundled fonts.
Design: `docs/rust-launcher.md`, `docs/rust-menu.md`. The C++ window (`launcher/launcher.cpp`
`RunGui`, `docs/launcher.md` "The window") is the behaviour to match; the colours are its `kUi*`
constants (dark grey panels, a light main button with dark text, green for good status).
Nothing here was run in game.

## Pages

| Page | What it does |
| --- | --- |
| Home | Verdict line, Status panel (`scol_install::collect_status`, same rows as the C++ panel), Play (Stop while the game runs), Update, check again, Repair banner when a PC-change record is left and no game runs (it runs `uninstall`). |
| Output | Streamed command output with Copy. |
| Plugins | Installed: list from `data\plugins`; On/Off toggle, Settings, Remove (asks once; settings are kept); "Add a plugin" from a folder or zip. All changes go through `scol-plugin-manager`, which verifies, stages transactionally, lands the plugin switched off and records it in `data\launcher\installed.json`. Native plugins show a native-code warning. Per-plugin settings page. Catalogue: see below. |
| Capabilities | Plain-words page, see below. |
| Settings | Repair, `clean_logs`, `language`, `menu` (Classic = `imgui`, New = `rust`, not tested in game yet), global `plugins`, `check_updates`, path of `sc-offline.ini` with Open. |

Keyboard: Tab walks the side list and then the page in reading order; Ctrl+1 to Ctrl+5 jump to a page;
F5 reads the status again. Toggles are reachable with Tab and switch with Space or Enter.

### Capabilities

Each of the six switches shows a short name, one sentence, an On/Off toggle and one evidence line
(`src/caps.rs`, text in `locale/extra_*.ini`, keys `launcher.ui.cap.<switch>.name|about`). The ini key
(`exp_*`), the capability name and the evidence level are only in the tooltip and in the collapsed
Details row. The test `caps::tests::main_text_has_no_raw_identifiers` walks every string shown without
Details, in both languages, and fails on `exp_`, `synthetic_only`, dotted names and similar.
Evidence lines come from the owner's in-game sessions on build 4.10.200.58746: gear equip through
`game.loadout.async` is "Seen working in game once"; everything else is "Not run in game yet".
Capabilities of `capabilities.json` that have no switch are read-only: "Works by itself, no switch"
(registry default ON) and "Not available yet" (registry default OFF, with the reason in plain words).
Defaults are not changed by any of this.

### Catalogue

The catalogue is read from a local folder, `data\launcher\catalogue`, holding `index.json`,
`index.json.sig` and the plugin zips (`scol_plugin_manager::fetcher::FileFetcher`). The index must be
signed by a key in the trust root. The shipped trust root is empty (no production signing key exists
yet), so the tab says "No catalogue is published for this build yet". Adding the production key is a
release-time step in `scol-catalogue`. First-party and reviewed plugins are offered, everything lands
switched off.

en and ru text: `src/locale_table.rs` is generated by `tools/gen_locale.py` from
`launcher/locale_strings.h`, `locales/launcher/ru.ini` and `locale/extra_*.ini` (run it after a locale
change; without `--write` it only checks). `i18n::tests::no_missing_keys_in_code` checks that every
text key named in `src/` exists in both languages. Capability names of rows without a switch are made
readable from the English capability words and stay English in the Russian window. Fonts: Segoe UI,
then Arial, Tahoma, Calibri and the Segoe symbol font as fallbacks, read from `%SystemRoot%\Fonts` at
run time (Cyrillic is covered). If none exists the window exits with an error. No font is embedded or
redistributed (eframe default features are off; `cargo deny check` of the workspace passes).

## Wiring (integrator)

* `scol_ui::run(&args) -> i32`: no option opens the window with `real::RealBackend`; `--here <folder>`,
  `--ui-self-test`, `--ui-screenshots <folder>`, `--help`.
* `scol_ui::run_window(here, Arc<dyn Backend>) -> i32`: use this to pass a backend of your own.
* `real::RealBackend::new(here)` (feature `real`, on by default) calls the library crates in this
  process, on the worker thread: Play and Repair through `scol_play::real::run_command_with` (with the
  update notice before Play), Stop through `scol_play::stop::stop_game` and `RealStop`, Update through
  `scol_update::run_with` (the button is the consent), open folder or file through `ShellExecuteW`. It sets
  `SC_OFFLINE_GUI=1` so nothing waits for Enter. The `scol-cli` crate has its own `WindowBackend` that
  runs the exe as a child; both work.
* `trait Backend` (`src/backend.rs`) keeps every earlier method (`run`, `game_running`, `fetcher`,
  `allowed_hosts`, `trust`, `open`) and adds `game_probe()`, `pick_folder(title)` and
  `save_plugin_setting(here, plugin, name, value)`. The last two are TEMPORARY: their defaults answer
  "... is not connected yet" and the window shows a plain sentence ("The folder picker is not in this
  build yet. Paste the path ..." and "Saving plugin settings from this window is not in this build
  yet."). `RealBackend` leaves them at the default until the folder dialog (`scol_play::pick`) and the
  plugin settings writer land.
* Cargo feature `fixtures` compiles in the golden index and the TEST key. For the self test and
  screenshots only; never enable it in a release build.

## Tests

* `cargo test -p scol-ui` (add `--features fixtures` to match CI of the self test): locale tables and
  the missing-keys scan, the capability wording test, and `tests/flows.rs` (add zip and folder, hostile
  zip refused, remove, a running game blocks changes, catalogue install from a local folder, changed
  download refused, empty trust root, unreviewed entries, bad signature, registry rows, Stop beside
  Play). No test starts a process or the game.
* `scol-ui --ui-self-test` (add `--features fixtures` to include the catalogue): builds every page for
  three frames in both languages on a fixture install under `D:\t`, no window and no GPU, then runs the
  page actions and checks the files they write. Exit 0 or 1.
* `scol-ui --ui-screenshots tests/ui/screens`: opens the real window (needs a display and OpenGL) and
  saves PNGs of the pages, scrolled parts and Russian text. `SCOL_UI_SHOT_SIZE=640x440` takes the shots at
  the smallest size to look for clipped text. The Home shot shows the status of the PC it was taken on.
