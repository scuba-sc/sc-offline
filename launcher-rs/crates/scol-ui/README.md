# scol-ui

The sc-offline launcher window in Rust: eframe 0.37 / egui 0.37, glow renderer, no bundled fonts.
Design: `docs/rust-launcher.md`, `docs/rust-menu.md`. The C++ window (`launcher/launcher.cpp`
`RunGui`, `docs/launcher.md` "The window") is the behaviour to match. Nothing here was run in game.

## Pages

| Page | What it does |
| --- | --- |
| Home | Verdict line, Status panel (`scol_install::collect_status`, same rows as the C++ panel), Play or Stop, Update, check again, Repair banner when a PC-change record is left and no game runs. |
| Output | Streamed command output with Copy. |
| Plugins | Installed: list from `data\plugins`, checkbox writes or deletes the `disabled` marker, plugin settings read-only, "Add from folder or zip" (`scol_plugins::verify` first, then extract with hash check; lands disabled). Catalogue: verified index through `scol-catalogue`, Install lands disabled with the native-code warning. |
| Capabilities | The `exp_*` switches as toggles that edit `sc-offline.ini` in place (`scol_config::ini_edit`), each with its text and "Not run in game."; `exp_entities_diag` is the diagnostic switch, off by default. Other capabilities from `capabilities.json` (next to the launcher, else the built-in table), read-only, with a filter. |
| Settings | Repair, `clean_logs`, `language`, global `plugins`, path of `sc-offline.ini`. |

en and ru text: `src/locale_table.rs` is generated by `tools/gen_locale.py` from
`launcher/locale_strings.h`, `locales/launcher/ru.ini` and `locale/extra_*.ini` (run it after a locale
change; without `--write` it only checks). Fonts: Segoe UI, then Arial, Tahoma, Calibri and the Segoe
symbol font as fallbacks, read from `%SystemRoot%\Fonts` at run time (Cyrillic is covered). If none
exists the window exits with an error. Nothing is embedded or redistributed.

## Wiring (integrator)

* `scol_ui::run(&args) -> i32`: no option opens the window; `--here <folder>`, `--ui-self-test`,
  `--ui-screenshots <folder>`, `--help`.
* `scol_ui::run_window(here, Arc<dyn Backend>) -> i32`: use this to connect real actions.
* `trait Backend` (`src/backend.rs`): `run(Command, here, out)` for Play, Stop, Update and Repair
  (`uninstall`), `game_running()`, `fetcher()` for catalogue downloads, `allowed_hosts()`, `trust()`
  (default: the built-in keys, which are none, so every index is refused until the production key is
  added in `scol-catalogue`), `open(path)`. Every default says "not connected yet" and the window shows
  "<action> is not available in this window yet. Run sc-offline.exe <command> from a terminal."
* Cargo feature `fixtures` compiles in the golden index and the TEST key. For the self test and
  screenshots only; never enable it in a release build.

## Tests

* `cargo test -p scol-ui`: locale tables, UTC text, and `tests/flows.rs` (add zip, hostile zip refused,
  catalogue install with a local fetcher, changed download refused, untrusted or unreviewed index,
  registry rows).
* `scol-ui --ui-self-test` (add `--features fixtures` to include the catalogue): builds every page for
  three frames in both languages on a fixture install under `D:\t`, no window and no GPU, then runs the
  page actions and checks the files they write. Exit 0 or 1.
* `scol-ui --ui-screenshots tests/ui/screens`: opens the real window (needs a display and OpenGL) and
  saves one PNG per page. Worked on this PC; the PNGs in `launcher-rs/tests/ui/screens` come from it.
  The Home shot shows the status of the real PC the shot was taken on.

## Numbers (2026-11-18, Windows x64, Rust 1.99.0)

* Release exe: 4,486,144 bytes (4.28 MiB), built with `RUSTFLAGS="-C target-feature=+crt-static -C link-arg=/Brepro --remap-path-prefix=<CARGO_HOME>=/cargo --remap-path-prefix=crates=/scol/crates"`.
  With only the `.cargo/config.toml` flags the exe is 4,492,800 bytes and holds about 286 registry paths
  with the builder's home folder in panic strings; the CARGO_HOME remap above removes them (checked with
  `strings`: no user name left).
* Crates: 124 unique in `cargo tree -p scol-ui -e normal` (windows target), 118 of them third-party.
* `cargo deny --manifest-path crates/scol-ui/Cargo.toml check`: advisories ok, bans ok, licenses ok,
  sources ok. Warnings only: duplicate `miniz_oxide` and `windows-sys`.
* Workspace-wide `cargo deny check`: licenses FAILED because `scol-menu` enables eframe `default_fonts`
  (`epaint_default_fonts`: OFL-1.1 AND Ubuntu-font-1.0). Not in this crate's graph unless both are
  built in one cargo command (feature unification then links the fonts into this exe too; they stay
  unused because the window loads `FontDefinitions::empty()`).
